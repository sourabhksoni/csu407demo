# Held out evaluation set

**Owner: Evaluation Lead. No code under `src/` or `models/` reads this directory.**

The brief names eval set contamination as a red flag requiring a fresh held out
set. Keeping the eval data on its own path, owned by a different team member
than the one training the adapter, makes that structural rather than a matter of
discipline. `evaluation/harness.py` additionally refuses to run if any record
here also appears under `data/processed/`.

## Format

One JSON object per line:

```
{
  "id":          stable identifier
  "modality":    api_csv | html_table | digital_pdf | scanned_pdf_ocr
  "language":    en | hi | mixed
  "source_id":   an id from config/sources.yaml
  "input_text":  the source text span handed to the model
  "ground_truth": the record a correct extraction produces, null for absent fields
  "provenance":  document_name and page_number
}
```

## Composition requirement

The set must span all four modalities, not only the easy ones. An eval set made
mostly of clean CSV rows flatters the baseline and hides what the adapter
contributes, because the adapter is trained precisely for the messy cases.

Target composition:

| Modality | Share | Why |
|---|---|---|
| api_csv | low | Deterministic path, the model barely participates |
| html_table | low | Mostly deterministic, escalated only on parse failure |
| digital_pdf | high | Where semantic extraction starts to matter |
| scanned_pdf_ocr | high | Hindi and OCR noise, the hardest case and the adapter's purpose |

At least one Hindi record is mandatory, since the Phase 2 gate tests at least one
non English document.

## Building it

Ground truth is written by hand against the original document. It is never
generated by the base model, because a set labelled by the model under evaluation
cannot measure whether adaptation helped.

The Agricultural Statistics at a Glance parallel English and Hindi editions are
useful here: extracting from the Hindi edition and checking against the English
edition gives a Hindi accuracy signal without hand labelling every example.

The two records currently in `extraction_eval.jsonl` are templates and must be
replaced before any reported number means anything.
